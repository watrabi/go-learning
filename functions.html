Functions and errors

Go functions can return more than one value, and that's how errors work: there are no exceptions, just a second return value you check.

Writing functions

        func add(a int, b int) int {
            return a + b
        }

        func swap(a, b string) (string, string) {  // same type? write it once
            return b, a
        }

        x, y := swap("left", "right")   // y is "left"

Types go after names. The return type goes after the brackets, and several return types go in their own brackets.

Errors are values

A function that can fail returns an error as its last value. nil means it worked. You check it straight away, every time. Pick some numbers and call div.

follow the error
                    func div(a, b int) (int, error) {
                        if b == 0 {
                            return 0, errors.New("can't divide by zero")
                        }
                        return a / b, nil
                    }

                    func main() {
                        q, err := div(a, b)
                        if err != nil {
                            fmt.Println("error:", err)
                            return
                        }
                        fmt.Println("result:", q)

defer

    
defer schedules a call to run when the surrounding function returns. It's how you make sure cleanup happens: open a file, then defer f.Close() on the next line. Deferred calls go onto a stack, so the last one deferred runs first.

Functions are values

    
You can store a function in a variable, pass it around, and return it. A function made inside another one remembers the variables around it. That's a closure.

    
        func counter() func() int {
            n := 0
            return func() int {
                n++
                return n
            }
        }
