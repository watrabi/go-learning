Structs and interfaces

Go has no classes. You group data with structs, attach functions to them as methods, and describe behaviour with interfaces.

Structs

        type User struct {
            Name  string
            Age   int
            admin bool   // lowercase: only this package can see it
        }

        u := User{Name: "ana", Age: 31}   // admin gets its zero value, false
        u.Age++
        fmt.Println(u.Name, u.Age)        // ana 32
        fmt.Printf("%+v\n", u)           // {Name:ana Age:32 admin:false}

Methods

A method is a function with a receiver: the value it's called on, written before the name.

        type Counter struct{ n int }

        func (c Counter) Value() int { return c.n }   // value receiver: gets a copy
        func (c *Counter) Inc()      { c.n++ }        // pointer receiver: changes the original
        func (c Counter) BadInc()    { c.n++ }        // changes a copy. does nothing useful

Rule of thumb: if any method needs a pointer receiver, give them all pointer receivers. You don't need to write (&c).Inc(); Go takes the address for you when c is a variable.

Interfaces

An interface is a list of methods. Any type that has those methods is that interface, automatically. There's no implements keyword. Tick methods on and off and see which types count as a Shape.

        type Shape interface {
            Area() float64
            Perimeter() float64
        }

This is why Go interfaces tend to be tiny. The standard library's io.Reader has one method, Read, and files, network connections, zip readers and strings all satisfy it without knowing it exists. Write functions that take small interfaces and they'll work with types you've never seen.






    
Embedding instead of inheritance

    
        type Animal struct{ Name string }
        func (a Animal) Hello() string { return "hi, I'm " + a.Name }

        type Dog struct {
            Animal          // embedded: no field name
            Breed string
        }

        d := Dog{Animal{"rex"}, "corgi"}
        fmt.Println(d.Hello())   // hi, I'm rex. Hello was promoted from Animal
    

    
A Dog has an Animal inside it and gets its methods. It isn't a subclass: you can't pass a Dog where an Animal is wanted. If you need that, use an interface.
