Pointers

A pointer holds the address of a value instead of the value itself. Go's pointers are the friendly kind: no arithmetic, and memory is cleaned up for you.

& and *

  • &x means "the address of x". If x is an int, &x is an *int.
  • *p means "the value p points at". You can read it or write to it.

Go passes copies

    
When you call a function, it gets a copy of each argument. Change the copy and the caller never sees it. Pass a pointer when the function should change the caller's variable.

    
        func double(n int)     { n = n * 2 }
        func doublePtr(n *int) { *n = *n * 2 }

Big structs are also often passed by pointer just to skip the copy. Slices and maps already contain a pointer inside, so passing them is cheap, and a function can change their elements.






    
Making pointers

    
        p := new(int)          // a pointer to a fresh zero int
        u := &User{Name: "bo"} // the usual way: address of a struct literal

        func newUser(name string) *User {
            u := User{Name: name}
            return &u          // totally fine in Go. u lives on after the function returns
        }
    

    

        
nil: A pointer's zero value is nil. Following a nil pointer (*p or p.Name) panics with "invalid memory address or nil pointer dereference". You'll meet this error. Everyone does.
