Goroutines and channels

This is the part Go is famous for. Starting concurrent work is one keyword, and goroutines talk to each other through channels.

Goroutines

Put go in front of a function call and it runs in a new goroutine, alongside everything else. The line returns immediately. Goroutines are cheap: a few kilobytes each, so running thousands is normal.

The catch: you don't control the order they run in, and when main returns, the program ends whether they're done or not. sync.WaitGroup waits for them.

        var wg sync.WaitGroup
        for _, name := range []string{"ana", "bo", "cy"} {
            wg.Add(1)
            go func() {
                defer wg.Done()
                work(name)
                fmt.Println(name, "finished")
            }()
        }
        wg.Wait()   // blocks until every Done has been called
        fmt.Println("all done")

Channels

    
A channel is a pipe with a type. One goroutine sends a value in, another receives it.

    
        ch := make(chan int)      // unbuffered
        go func() { ch <- 42 }()  // send
        v := <-ch                 // receive. waits until a value arrives
    

    
The important part is when they wait. On an unbuffered channel a send waits until someone receives, so the two goroutines meet. A buffered channel has room for a few values, and senders only wait when it's full. Each button press below is a new goroutine.

When you're done sending, close(ch). Receivers can then loop with for v := range ch, which stops after the last value. Only the sender should close a channel, and sending on a closed one panics.

    

        
deadlock: If every goroutine is stuck waiting on a channel, Go stops the program with fatal error: all goroutines are asleep - deadlock!. The classic way to get it: send on an unbuffered channel in main with nobody to receive.

    






    
select

    
select waits on several channel operations at once and runs whichever is ready first. It's how you add timeouts:

    
        select {
        case msg := <-messages:
            fmt.Println("got", msg)
        case <-time.After(2 * time.Second):
            fmt.Println("gave up waiting")
        }
    

    
Go's motto for all this: don't communicate by sharing memory; share memory by communicating. When goroutines must share a variable, protect it with a sync.Mutex, and run your tests with go test -race to catch mistakes.
