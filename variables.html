Variables and types

Go is statically typed: every variable has one type, fixed when the program compiles. You usually don't have to write the type out, though. Go works it out.

Three ways to declare

        var age int = 30      // the long way: name, type, value
        var name = "gopher"   // the type comes from the value
        score := 100          // short form. only inside functions

        var a, b int = 1, 2   // several at once
        x, y := 10, "ten"     // different types are fine

Inside functions, almost everyone writes :=. You'll see var at package level (where := isn't allowed) and when you want a variable to start at its zero value.

Zero values

A variable you don't give a value isn't garbage or undefined. It gets the zero value for its type. Pick a type to see what var x holds.

zero value explorer
var x int
x0

This is why Go code rarely checks "was this set?". A counter that starts at 0 or a string that starts empty is usually exactly what you wanted.

What type did I get?

With := the type comes from the right-hand side. Type an expression (or pick one) and see what Go would make of it.

type inference
x :=

no surprise conversions: Go never converts between types for you. var f float64 = n fails if n is an int. Write float64(n). It feels strict at first, and it removes a whole category of bugs.

Constants

        const Pi = 3.14159
        const greeting = "hello"

        const (
            Small = iota  // 0
            Medium        // 1
            Large         // 2
        )

Constants are fixed when the program compiles. iota counts up inside a const block, which is Go's way of doing enums.
